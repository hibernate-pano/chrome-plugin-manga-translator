# Spec — 漫画翻译助手 · UI 重设计

## 产品是什么

Chrome MV3 扩展。用户在漫画 / 条漫页面上右键或点工具栏，扩展把图片交给用户自己配置的
视觉模型（MiniMax、OpenAI 兼容、Ollama、LM Studio），把译文画回原图的气泡位置。
没有开发者后端，没有账号，没有遥测；API Key 只在本机。

## 这次要设计的面

| 面 | 尺寸 / 场景 |
| --- | --- |
| 弹窗 | 360×600–640，Chrome 工具栏点开，最高频 |
| 设置页 | 全页，960–1120 内容宽，配置服务商、语言、分辨率、并发、单价 |
| 引导 | 首次安装，3 步内完成「知情 → 选服务商 → 填 Key」 |
| HUD | 页面右下角，翻译中 / 失败时出现，必须不挡漫画 |
| 阅读面板 | 页面右侧 320px，列出本页译文，可按图跳转 |

## 受众与场景

- 中文读者，18–35 岁，读日漫、韩漫、条漫；对「这一页要花多少钱」敏感。
- 已经有一个模型服务或本地 Ollama；愿意填 Key，但不想读说明书。
- 在别人的页面上工作：HUD 和阅读面板必须克制、可关闭、不抢画面。

## 核心任务（按优先级）

1. **花之前知道**：这一页有几张图、几张还没加载、缓存命中多少、重翻会不会再计费。
2. **开始 / 停止**：一个明确的主按钮；运行中能看到进度、剩余时间、取消真的停。
3. **失败可修**：哪张失败、为什么、重试只重试失败的那几张。
4. **配置不迷路**：服务商预设、Base URL、模型、Key、测试连接、目标语言、分辨率、并发、单价。
5. **读译文**：右侧面板按阅读顺序编号，原文/译文可对照，点编号跳到图。

## 情感基调

编辑部的工具，不是企业的仪表盘。有判断、有留白、有纸感或墨感；不卖萌，不堆卡片，
不用「大数字 + 小标签 + 渐变」当默认答案。用户打开它是因为要读漫画，不是要玩设置。

## 硬约束

- 中文文案，正文 ≥14px，标签 ≥12px，正文对比度 ≥4.5:1，可点目标 ≥44×44。
- 弹窗固定 360 宽；设置页在 960–1120 宽内可读；不做移动端。
- 扩展页面可以用浅色或深色，但必须是一个完整的主题，不能半黑半白。
- HUD / 阅读面板在任意网页上都要能读：不依赖页面字体，不假设页面底色。
- 真实素材：`store/artwork/manga-page-1.png`、`store/demo/demo-manga-page-1.png`。
- 不编造用户评价、下载量、logo 墙。

## 输出格式（三版统一）

每个方向一张 1440×1100 的设计板：

- 左：弹窗 360×640（空闲态）+ 运行态小样。
- 中/右：设置页 760×640 的可见片段。
- 底：在真实漫画裁切上展示 HUD 与阅读面板。
- 顶部：方向名、来源、借用的规则、form 来自内容的哪里。

## form 五问（每版答一次）

1. 叙事角色：读者在故事页上做事，界面是旁注不是主角。
2. 观众距离：手臂长度，弹窗 30cm，设置页 50cm。
3. 视觉温度：由方向决定；一版安静、一版冷硬、一版响亮。
4. 容量：弹窗 5 个决策点以内；设置页 4 个分区。
5. 视觉母题：来自漫画制作本身——分镜、校正、印刷、网点，而不是通用 SaaS。

## 不做什么

- 不重做信息架构到「Dashboard」：这仍然是一个弹窗 + 一个设置页。
- 不改翻译管线、缓存、计费逻辑；只改呈现与交互。
- 不引入外部字体 CDN；用系统字体栈，保证扩展离线可用。
